    user {
        text id PK
        text name
        text email UK
        boolean email_verified
        timestamp created_at
    }
    session {
        text id PK
        text token UK
        text user_id FK
        timestamp expires_at
    }
    account {
        text id PK
        text provider_id
        text account_id
        text password
        text user_id FK
    }
    verification {
        text id PK
        text identifier
        text value
        timestamp expires_at
    }
    centres {
        uuid id PK
        text nom
        text user_id FK
        timestamp created_at
    }
    documents {
        uuid id PK
        text nom_etudiant
        text cours
        text statut
        uuid centre_id FK
        timestamp created_at
    }

PK = cle primaire · FK = cle etrangere · UK = champ unique
user, session, account, verification : tables de Better Auth (authentification) · centres, documents : tables metier de Sank.
centres.user_id porte un index UNIQUE : un directeur ne detient qu'un centre en V1 (le guide du staff reste possible plus tard). documents.statut = "En attente" ou "Envoye" (contrainte applicative ; la suppression d'un centre casse ses documents).
verification n'a pas de FK : elle relie un email (identifier) a un code, pour la verification d'adresse.
